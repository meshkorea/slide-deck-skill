# 슬라이드 덱 만들기 (딥 네이비 · 큰 타이포 스타일)

발표 덱은 **자립형 HTML 한 장** — `1280×720` 스테이지를 뷰포트에 맞춰 스케일하고,
`.slide.active` 토글로 한 장씩 넘긴다. 폰트·CSS·내비게이션 스크립트가 전부 파일 안에 인라인.
빌드 단계 없음. 만든 뒤에는 **헤드리스 Chrome으로 PNG를 뽑아 눈으로 확인**한다 —
`render.mjs`가 그 드라이버다.

시작 템플릿(표지·한 줄 슬라이드·제목+불릿 3종·여정·사분면·표·코드 2종·포커스 버스트 원형 슬라이드 + 전 CSS)은 이 스킬에 동봉된
`reference/deck-template.html`. 편집할 덱 파일 경로는 **지금 작업 중인 프로젝트 기준**이다.
덱을 만든 뒤에는 **발표자용 개요 마크다운을 함께 낸다** — `outline.mjs`가 덱에서 뽑아준다.

> **스킬 파일 위치.** 아래 명령들은 동봉된 드라이버·템플릿을 `$SD` 로 참조한다.
> 세션 셸에서 한 번 정의하고 시작:
> ```bash
> SD="${CLAUDE_PLUGIN_ROOT:+$CLAUDE_PLUGIN_ROOT/skills/slide-deck}"
> SD="${SD:-.claude/skills/slide-deck}"   # 저장소에 직접 둔 경우 폴백
> ls "$SD/render.mjs"                       # 경로 확인
> ```
> `$CLAUDE_PLUGIN_ROOT` 가 셸에 없으면 이 스킬이 로드된 실제 디렉토리 절대경로를 `$SD` 로 삼을 것.

## 스타일 규약 (사용자 확정 — 어기지 말 것)

이 스타일의 덱은 "AI가 뽑을 것 같은" 기본값을 의도적으로 피한다. 아래는 반복 교정으로 굳은 규칙.

**타이포 — 크게, 카피는 줄여서**
- 폰트는 **덱마다 하나만** 골라 쓴다(한 덱 = 한 폰트, 도중 교체 금지). 기본은 **Asta Sans**(fonts-archive CDN, 300–800). 새 덱은 아래 [폰트 선택](#폰트-선택) 프리셋에서 사용자에게 물어 정한다. **모노스페이스 금지** — 라벨·날짜·경로 표기에 고정폭 쓰지 말 것. **유일한 예외는 [코드 스니펫](#코드-스니펫)**(`pre.code`·`code.inl`) — 거기선 열 정렬이 의미를 가지므로 고정폭 `--font-code`를 쓴다. (과거엔 Asta Sans 단일·모노 전면 금지가 규칙이었으나, 폰트는 프리셋 선택으로, 모노는 코드 한정 예외로 완화됨.)
- 본문 **32px 권장** (@1280×720). 24px도 작다는 의견이 많아 기본을 키웠다 — 리스트·표·밴드·flow·사분면 본문은 CSS 변수 `--body`(기본 32px)를 공유한다. 꽉 차서 넘치면 **먼저 카피를 줄이고**, 그래도 안 되면 장에 `.dense`(→ `--body` 26px)로 한 단계 축소. **24px 밑으로는 절대 내리지 말 것**(하한).
- 캡션·라벨·표 헤더는 CSS 변수 `--cap`(기본 **24px**)을 공유한다. `.ctx`(맥락 라벨)만 25px. 표 헤더행·`.lbl`·스텝 설명·수치 설명이 여기 묶인다 — 18px대로 쪼그라들지 않게 한 게 기본값. 캡션도 **≥20px** 유지.
- 자간으로 위계를 준다 — **제목 -0.04em**(디스플레이 h1·`h2.title`·표지 제목), **본문·캡션 -0.02em**(리스트·표·밴드·flow·사분면 + `.ctx`·`.lbl`·표 헤더·수치/스텝 설명). 제목이 본문보다 촘촘해야 단단해 보임. 한글이라 본문·캡션은 -0.02em이 상한(더 조이면 가독성 저하).
- 제목만 크고 본문이 문서 크기(≤16px)인 건 금지 — "PPT 시절이면 혼났을 사이즈". 아래가 비면 카피를 줄이고 글씨를 더 키운다.
- 제목 50px / 표지 100px 안팎 / 한 줄 슬라이드 100–128px. 표지 부제(키워드 줄)는 31px 안팎으로 본문급 존재감을 준다.

**말투 — 간결·음슴체·마침표 최소**
- 제목·슬로건: 문장을 완성하려 하지 말고 **명사형으로 끊는다**. 어미·마침표 제거 ("사용자는 넷이다." → "사용자는 넷").
- 본문·테이크어웨이: **음슴체(-함/-됨/-음)** 또는 명사구. 문장 끝 마침표 잘 안 찍음.
- 라벨은 "~할 것", 표 헤더·항목은 평문 명사형.
- **의인화·문학적 은유 금지** ("세일즈 웹 안에서 태어난다" 류), **임의 축약 금지** ("시뮬레이션"을 "시뮬"로 X). 확신 없으면 전체 표기.

**레이아웃 — 텍스트를 사각 틀에 가두지 않는다**
- 구획은 **테두리 박스가 아니라 가는 줄(hairline)·상단 괘선·여백**으로. 표(`table.min`)는 세로 괘선·셀 배경 없이 상단 프라이머리 괘선 + 행 hairline만. 사분면(`.quad`)·밴드(`.band`)도 위쪽 줄 하나로만 나눈다.
- 아키텍처 다이어그램의 서비스 블록처럼 **네모가 의미를 갖는 곳만** 테두리 허용. 일반 텍스트 그룹핑에 카드/패널 쓰지 말 것.
- **제목 + 불릿(구분점)이 가장 흔한 워크호스 장이다.** 단순 나열은 표(`table.min`)나 사분면(`.quad`)으로 우회하지 말고 이걸 쓴다 — 표는 2열 이상 대응 관계가 실제로 있을 때만, 사분면은 2×2 대비 구조일 때만. 세 결을 내용에 맞춰 고른다: `ul.bul`(작은 프라이머리 사각 마커 — 한 줄로 끝나는 일반 불릿) · `.rows`(항목마다 제목+설명 두 줄, 위쪽 hairline 으로만 구분) · `ol.num`(01/02 넘버 — 순서·우선순위가 있을 때, 사분면의 원문자 ①②③와 구별). 구분점은 **작은 프라이머리 사각 · hairline · 넘버로만 — 카드·패널 금지**(포인트색을 텍스트 옆 사각 마커로 쓰는 건 여전히 금지 — 범례처럼 보임). 마커·넘버는 텍스트 첫 줄 높이 중앙에 정렬. 항목은 3~5개, 리드는 굵게 + 꼬리 설명은 회색(`<span>`). 하위 항목은 `ul.bul` 안에 `<ul>` 을 중첩하면 **더 작고 흐린 사각으로 한 단계 들여쓰기**된다(2단까지만 — 폰트는 안 줄이고 마커 크기·색·들여쓰기로만 위계, `--body` 24px 하한 유지).
- 한 장 = 한 생각. 여백 중심(애플 키노트 결). 리듬용으로 **한 줄 슬라이드**(`.one-liner`, 네이비 필드 + 흰 글자)를 섹션 브레이크로 사이에 낀다.

**컬러 — 프라이머리 1색 + 포인트 3색, 포인트는 밑줄로만**
- 프라이머리(메인)는 `--blue` 하나(변수명은 레거시 — 실제 색은 덱마다 다르니 "블루"라 부르지 말 것). 한 줄 슬라이드 배경·결정 문장·강조 수치·스케치·`.ul.blue`가 전부 이걸 따른다. 포인트는 `--mint #43D6AE`(oklch 0.789 0.136 171) · `--pink #F186B0`(0.748 0.138 356) · `--sky #60BEFC`(0.77 0.126 240, 라이트 블루) **3색** — 셋 다 L≈0.77·C≈0.13 파스텔로 서로 자매색. 밑줄은 `.ul.mint/.pink/.sky`. 쨍한 원색 금지.
- **프라이머리 컬러는 덱마다 골라 바꾼다.** `:root`의 `--blue`는 `oklch(var(--main-l) var(--main-c) var(--main-h))` — **명도(`--main-l`)·채도(`--main-c`)는 딥 네이비 톤 그대로 두고 색상(`--main-h`)만 교체**하면 정체성이 바뀐다. 기본은 딥 네이비 `oklch(0.385 0.09 272)`(=`#333F73`). 프리셋: 인디고 290 · 딥 플럼 320 · 와인 15 · 러스트 45 · 포레스트 150 · 딥 틸 195 · 오션 230. 청록 계열(틸·오션)만 이 명도에서 채도가 덜 붙으니 `--main-l:0.40 --main-c:0.068`로 함께 낮춰 깊이를 맞춘다. 프리셋 표는 템플릿 `:root` 주석에 있다.
- 포인트는 **텍스트 아래 형광펜식 밑줄**(`.ul.mint/.pink/.blue`)로만 — 글자색 입히기·텍스트 옆 사각 마커 금지("범례처럼 보인다").
- 색에 의미를 실을 것(예: 프로젝트별 색 고정).
- **글자색 금지의 예외는 코드 블록 구문 색 하나**다 — Catppuccin 계열 **별도 팔레트**(기본 Latte, `.dark` 필드는 Mocha)를 쓰고 포인트 3색과 섞지 않는다. 자세한 건 [코드 스니펫](#코드-스니펫).

**스케치 레이어 — 손그림 연필 톤**
- 강조 대상에 손그림 **링(`.ring`)·밑줄 스와시(`.swash`)·유도 화살표(`.sk`/`.ska`)** SVG. 프라이머리 단일, 한 줄 슬라이드에서만 흰색. 획 불투명도 .55(연필 메모 톤, 진하게 금지). 화살표는 바깥→안쪽, 장당 가리키는 대상 하나.
- 경로 스케치는 **방향이 단조로워야** 한다 — 좌우로 배가 나오는 곡선은 어긋나 보임. 화살촉은 선의 도착 접선에 정확히 얹는다.
- **템플릿에 박힌 스케치(특히 한 줄 슬라이드의 사선 화살표)를 매 덱에 그대로 복붙하지 말 것.** 그건 예시일 뿐 — 장마다 **실제로 강조할 대상을 가리키게** 위치·방향·모양을 새로 잡는다. 가리킬 대상이 없으면 **차라리 생략**(장식용 화살표를 아무 데나 흘리면 AI 티). 표지 모티프와 같은 원칙 — 고정 도안이 아니라 그 장 내용에 맞춰 그린다.

**배경 장식 — 포커스 버스트 · 필러(빈 곳 채우기)**
- 유도 화살표보다 한 톤 더 흐린 배경 낙서로 **여백을 채우고 시선을 모은다**. 유도용은 대상을 "가리키고", 배경 장식은 여백을 "메꾸는" 역할 — 둘을 섞지 말 것.
- **포커스 버스트(`.sk.focus`)** — 한 지점을 감싸 안쪽으로 모이는 화살표 무리(불투명도 .4). 강조할 단어·수치 위에 `left/top/width/height`로 얹어 감싼다. **화살표가 텍스트에 닿으면 안 된다** — 안쪽(빈 중앙)을 넓게 잡아 글자가 그 안에 들어오게. 넓은 텍스트엔 좌우로 늘린 타원 배치를 쓰고 **수평 화살표는 빼서** 글자 끝과 안 부딪히게 한다. 템플릿 9번 슬라이드가 그 예시(타원 580×360, 8개). 한 장에 버스트는 하나만.
- **필러(`.sk.faint`)** — 빈 곳을 채우는 손그림. **작게 찍으면 성의 없는 낙서로 보인다 — 크게 그리고 아주 옅게(불투명도 .12) 깔아 "배경 텍스처"로 읽히게** 한다. `.thin`으로 획까지 얇게. 준비된 도안: **등고선 곡선**(사이드로 흐르는 평행선), **대각 해칭**(넓은 사선 밭), **점선 물결**(`stroke-dasharray="1 12"`).
- **필러는 화면 가장자리로 확실히 뺀다 — 사방에 여백을 두고 화면 안쪽에 뚝 놓지 말 것.** 그러면 배경이 아니라 둥둥 뜬 오브젝트로 보인다. 반드시 한쪽(또는 여러) **화면 끝에 붙여 잘리듯 배치**(edge-bleed)해 프레임 밖으로 이어지는 배경처럼 읽히게 한다. 등고선은 한쪽 사이드 스트립, 해칭은 코너에서 모서리 두 변에 붙게. 여백 안에 정사각으로 얌전히 앉힌 필러는 금지.
- **펜타그램(`.sk.star`)** — 여백 액센트. 별을 한 붓으로(0→2→4→1→3→0) 살짝 삐뚤게 그린 것(불투명도 .22로 필러보단 진하게). 반짝임(sparkle)보다 손맛이 산다. 표지 우상단 예시. 1~2개만.
- **양 조절이 핵심** — 배경 장식은 장당 1~2개까지. 텍스트·유도 스케치와 겹치지 않는 진짜 빈 곳에만.
- 배경 장식만은 **포인트 3색 허용**(`.sk.mint/.pink/.sky`) — 밑줄 전용 규칙과 별개다. 단 흐린 톤 유지, 쨍하게 금지. 한 줄 슬라이드에선 자동으로 흰색(필러는 더 은은).

**표지 모티프 — 매번 같은 그림으로 시작하지 않는다**
- 표지(및 필요한 장)의 배경 장식은 **덱 주제에 맞춰 그때그때 새로 그린다.** 모든 덱이 등고선+별로 시작하면 템플릿 티가 난다 — 템플릿 표지에 들어간 필러는 **기본값일 뿐, 주제 모티프로 교체하는 걸 권장**.
- 제목·주제를 한눈에 떠올리게 하는 **간단한 라인 드로잉**을 손그림 톤으로. 주제에서 바로 연상되는 사물 하나를 몇 개의 path로 그린다. 예: 배송·물류 → 경로 점선+위치 핀+트럭 윤곽 / 데이터·지표 → 꺾은선·막대 끄적임 / 사람·조직 → 단순 인물·말풍선 / 시간·일정 → 시계·달력 선 / 성장 → 우상향 곡선 화살표.
- 기법: 기존 스케치와 같은 톤으로(`.sk` 재사용, 둥근 획 끝, 손맛). **path만 쓸 것** — `<circle>`·`<rect>`는 `.sk path` 스타일이 안 먹어 검게 칠해진다. 원·바퀴·점도 `a`(호) 명령 path로 그린다. 색은 프라이머리 또는 포인트 1색. **필러 톤(`.faint`, 불투명도 .12)이면 배경 텍스처로, 그냥 `.sk`(.55)면 표지 액센트로 또렷하게** — 표지 일러스트는 보통 후자.
- **제목·부제를 가리지 않게** 한쪽 여백/코너에 두고, 디테일 과하게 넣지 말 것(라인 몇 개면 충분). 그린 뒤 **반드시 렌더로 확인** — `.sk`는 절대 좌표라 위치·크기는 눈으로만 잡힌다.
- 같은 모티프를 모든 장에 복붙하지 말 것 — 표지에만 두거나, 장마다 다르게.

**금지 (AI 티) — 넣지 말 것**
- 페이지 번호·하단 푸터 라벨, 슬라이드 위 운영 메타 텍스트(발표 시간·논의 시간 등 → 기획 md·[발표 개요](#발표-개요-뽑기)에만), 파스텔 패널, 알약 태그, 자간 벌린 영문 kicker, 배경 워터마크 숫자. S번호 관리는 HTML 주석으로만.

### 코드 스니펫

코드는 이 스타일에서 **모노스페이스와 글자색이 동시에 허용되는 유일한 자리**다 — "네모가 의미를 갖는 곳만 테두리 허용"과 같은 결의 예외다(들여쓰기·열 정렬·토큰 구분이 곧 의미). 예외는 **`pre.code`·`code.inl` 안쪽에서만** 성립하고, 라벨·경로·본문은 여전히 덱 폰트다.

- **폰트는 `--font-code` 고정** — `Monoplex KR Wide Nerd`(IBM Plex Mono + IBM Plex Sans KR). 라틴 0.6em · 한글 1.0em으로 정확히 2:1이라 한글 주석이 섞여도 열이 안 어긋난다. 덱 폰트를 무엇으로 골랐든 코드 폰트는 바꾸지 않는다. **`letter-spacing`은 0** — 자간을 건드리면 고정폭이 깨진다.
- **슬라이드 배경이 라이트니 코드도 라이트가 기본** — 옅은 잉크 틴트 + 좌측 프라이머리 괘선 + Catppuccin Latte 구문 색. **다크(프라이머리 네이비 필드 + 흰 코드 + Mocha)는 `class="code dark"`이고, 사용자가 다크 코드를 원한다고 말했을 때만 쓴다** — 라이트 덱에 다크 블록을 기본으로 깔면 그 장만 무거워진다. 필드는 **코드를 감싸게 줄어든다**(shrink-to-fit) — 긴 줄이 많아 어차피 꽉 찰 때만 `.wide`로 열 전체를 채운다.
- **분량 상한** — 전면 블록은 `--code` 24px에서 **한 줄 64자 · 10줄**, 코드+설명 2단(`.codecols`)은 21px에서 **36자 · 13줄**. **20px 밑으로는 금지.** 넘치면 폰트를 줄이지 말고 **발췌하거나 `…`로 접는다** — 슬라이드에 파일을 다 붙이지 않는다.
- **구문 색은 6역할까지** — `.k` 키워드 · `.s` 문자열 · `.f` 함수 · `.t` 타입 · `.n` 수치 · `.c` 주석. Catppuccin 톤으로 차분하게(기본 Latte / `.dark` Mocha — 필드에 맞춰 자동 교체됨). **역할을 더 늘리지 말 것**(무지개 하이라이팅 금지), 덱의 포인트 3색과 섞지 말 것.
- **강조는 `.hl`(형광펜식 인라인 배경)로 장당 한 곳**, 지금 다루지 않는 줄은 `.dim`으로 물린다 — 지우지 말고 흐리게 남겨 맥락을 유지한다. `.dim`은 구문 색 위에 곱해지므로 그 안 주석은 거의 안 읽힌다(그게 의도).
- **변경 전후는 `.del`/`.add`** — 줄 앞 `-`/`+`는 CSS 거터가 아니라 **코드 안에 글자로 직접 적고** 배경만 옅게 깐다. 줄 번호는 쓰지 않는다(가리킬 줄은 `.hl`로 가리킨다).
- **작성 시 주의** — `pre` 안은 `white-space: pre`라 HTML 소스의 들여쓰기가 그대로 코드 들여쓰기다. **코드는 열 0에서 시작**해야 하고, `<pre class="code">` 바로 뒤 줄바꿈은 파서가 버리지만 `</pre>` 앞 줄바꿈은 빈 줄로 남으니 붙여 쓴다. `<`·`&`는 `&lt;`·`&amp;`로 이스케이프.
- **파일 경로 캡션은 `.lbl`**(덱 폰트) — 경로에 모노 쓰지 말 것. 본문 속 짧은 식별자는 `code.inl`이 있지만 남발 금지 — 대개 `<b>` 굵게로 충분하고, 장당 두세 개까지.

> 덱마다 파일 상단 HTML 주석에 **디자인 브리프**(구조·말투·용어·컬러·변경 이력)를 명문화한다. 템플릿 상단 주석이 그 예시.

## 새 덱 만들기

### 시작 전 — 사용자에게 먼저 묻는다

바로 코드로 뛰어들지 말고, 아래 넷을 먼저 물어 방향을 맞춘다. `AskUserQuestion`으로 한 번에 묶어 물으면 깔끔하다. 사용자가 "빨리·대충·알아서"라고 하거나 답이 없으면 **묻지 말고 괄호 안 기본값**으로 진행한다.

1. **구성·분량** — 몇 부(챕터)로 나눌지, 심플하게 갈지 촘촘하게 갈지, 대략 몇 장인지. *(기본: 심플하게 · 표지 1 + 본문 6~10 + 마무리 1)* 부로 나눌 땐 각 부 앞에 **한 줄 슬라이드(`.one-liner`)를 섹션 브레이크로** 끼워 리듬을 준다. 분량이 늘면 한 장에 몰지 말고 장을 쪼갠다("한 장 = 한 생각").
2. **폰트** — 아래 프리셋 중 하나 → [폰트 선택](#폰트-선택) *(기본: Asta Sans)*
3. **메인 컬러** — 프리셋 중 하나 → [메인 컬러](#메인-컬러) *(기본: 딥 네이비)*
4. **마무리 결** — 감사 인사(Thanks) / End of Document 중 하나 → [마무리 장](#마무리eod-장) *(기본: 감사 인사)*

### 템플릿 복사

```bash
cp "$SD/reference/deck-template.html" slides/2026-07-my-deck.html
```

`<section class="slide">`를 추가/편집해 장을 늘린다. 각 `<section>` 위에 `<!-- S번호 · 요지 -->` 주석으로 관리. 슬라이드 수는 `render.mjs`가 자동으로 센다(주석 처리한 장은 빼고 셈).

### 폰트 선택

폰트는 **덱마다 하나**. noonnu.cc에서 받을 수 있는 무료 글꼴을 fonts-archive CDN으로 부른다. 아래 프리셋을 제시해 하나 고르게 하고, `:root`의 `--font`와 상단 `<link href>`를 **짝으로** 교체한다(한쪽만 바꾸면 안 먹음).

| 이름 | `<link>` 파일명 | `--font` family | 웨이트 | 결 |
|---|---|---|---|---|
| **Asta Sans**(기본) | `AstaSans` | `"Asta Sans"` | 300–800 | 개성 있는 지오메트릭 · 이 스타일의 시그니처 |
| 페이퍼로지 | `Paperlogy` | `"Paperlogy"` | 100–900 | 둥근 디스플레이 · 표지·한 줄 슬라이드에 강함 |
| 프리텐다드 | `Pretendard` | `"Pretendard"` | 100–900 | 가장 무난한 본문용 산세리프 |
| 수트(SUIT) | `SUIT` | `"SUIT"` | 100–900 | 모던·중립 · 정보 밀도 높은 장 |
| G마켓 산스 ※ | `GmarketSans` | `"Gmarket Sans"` | 300·500·700 | 또렷한 브랜드 톤 |
| 나눔스퀘어 네오 ※ | `NanumSquareNeo` | `"Nanum Square Neo"` | 300·400·700–900 | 각진 고딕 · 힘 있는 제목 |
| 나눔스퀘어 ※ | `NanumSquare` | `"Nanum Square"` | 300·400·700·800 | 클래식 고딕 |

`<link>` URL은 `https://cdn.jsdelivr.net/gh/fonts-archive/<파일명>/<파일명>.css` 꼴(예: `.../fonts-archive/Pretendard/Pretendard.css`). **※ 표시**는 웨이트 단계가 성겨(500·600 없음) 제목/본문 위계가 살짝 뭉갤 수 있으니 골랐으면 **렌더로 확인**한다. 스타일 규약(큰 타이포·자간·음슴체 등)은 폰트가 바뀌어도 그대로 유지.

**코드 폰트(`--font-code`)는 이 선택 대상이 아니다** — 어떤 덱 폰트를 골랐든 `Monoplex KR Wide Nerd` 고정이고, 두 번째 `<link>`도 그대로 둔다([코드 스니펫](#코드-스니펫)). 코드 장이 없는 덱이면 글리프를 안 받으니 링크가 남아 있어도 무해하다.

### 메인 컬러

**메인 컬러도 먼저 사용자에게 묻는다.** 어떤 메인 색으로 갈지 프리셋(딥 네이비 기본 · 인디고 · 딥 플럼 · 와인 · 러스트 · 포레스트 · 딥 틸 · 오션)을 제시해 하나 고르게 하고, 정한 값으로 `:root`의 `--main-h`(청록 계열이면 `--main-l`·`--main-c`까지)를 바꾼다. 사용자가 "알아서" 하라거나 별말 없으면 **기본 딥 네이비**로 둔다. 색은 한 덱 안에서 고정 — 도중에 바꾸지 말 것.

### 마무리(EOD) 장

덱은 **항상 EOD 클로징 한 장**으로 끝낸다 — 본문이 툭 끊기지 않게. 템플릿 마지막 `<section>`이 그 자리다. 두 결 중 하나만 남긴다:

- **감사 인사 결**(기본, 템플릿에 활성) — 한 줄 슬라이드 톤 네이비 + 큰 "들어주셔서 고맙습니다" + 좌하단 각주(팀·담당·Q&A 안내). 발표 마무리에 자연스럽다.
- **End of Document 결**(템플릿에 주석으로 동봉) — 페이퍼 배경 + 담담한 문서 종료 표기. 사내 공유용·읽는 자료에 어울린다. 쓰려면 감사 결 `<section>`을 지우고 아래 주석 블록을 푼다.

문구는 음슴체·명사형 규약 그대로("Thanks for listening"처럼 자간 벌린 영문 kicker 금지). 팀명·담당자는 실제 값으로 채운다.

## 렌더링·확인 (에이전트 경로 — 우선)

만들거나 고친 뒤 **반드시 렌더해서 실제 모습을 본다.** 코드만 읽고 넘어가지 말 것 — 폰트 로드·스케치 위치·넘침은 눈으로만 잡힌다.

```bash
# 전 슬라이드 → slides/.render/slide-01.png ...
node "$SD/render.mjs" slides/2026-07-my-deck.html

# 특정 장만
node "$SD/render.mjs" slides/2026-07-my-deck.html --slide 3

# 범위만
node "$SD/render.mjs" slides/2026-07-my-deck.html --range 1-5
```

출력은 기본 `<덱과 같은 폴더>/.render/slide-NN.png`. `--out DIR`로 바꿀 수 있다.
렌더된 PNG를 Read로 열어 타이포 스케일·색·넘침·스케치 위치를 확인한다.

폰트 로드 대기는 자동이다 — **코드 장이 있는 덱은 12초, 없으면 4초**(고정폭 웹폰트가 웨이트당 ~800KB라 4초로는 시스템 폰트로 폴백된 스크린샷이 나온다). 느린 회선에서 폰트가 여전히 안 붙으면 `--wait 20000`으로 직접 늘린다.

## 발표 개요 뽑기

**덱을 만들 때 기획 md가 없었으면(대화로 바로 덱을 뽑은 경우) 발표자용 개요 마크다운을 반드시 함께 낸다.** 발표 중에는 슬라이드에 안 적은 것들이 필요하다 — 순서, 무슨 말을 할지, 어떤 질문이 올지. 덱 HTML이 유일한 원본이므로 개요는 **손으로 쓰지 말고 덱에서 뽑는다.**

```bash
# 덱 → slides/2026-07-my-deck-outline.md
node "$SD/outline.mjs" slides/2026-07-my-deck.html

# 파일로 안 쓰고 먼저 보기
node "$SD/outline.mjs" slides/2026-07-my-deck.html --stdout

# 덱을 고쳐서 다시 뽑을 때 (기존 파일 덮어씀)
node "$SD/outline.mjs" slides/2026-07-my-deck.html --force
```

뽑히는 것: 덱 제목·장수 요약 → **흐름 한눈에** 표(장별 결·제목) → 장별 상세(맥락 라벨·제목·본문 블록·표·코드 블록·각주·한 줄 결론). 코드 장은 펜스 코드 블록으로 나오고 `.hl` 강조 줄·diff 증감·`.dim` 줄 수가 따라붙는다.

**뽑은 뒤 에이전트가 채울 것** — 각 장 밑에 `> 말할 것 — …` 한 줄을 붙여 완성한다. 슬라이드에서 금지된 **운영 메타(장별 목표 시간·총 발표 시간·예상 질문과 답)**도 이 문서에 넣는다 — 개요 md가 그것들의 정당한 자리다.

- 기존 개요 파일이 있으면 `--force` 없이는 쓰지 않는다(손으로 덧붙인 발표 포인트 보호). 덱을 고쳐 다시 뽑으면 그 추가분은 사라지니, **덱을 확정한 뒤에 채운다.**
- 기획 md가 이미 있는 작업이면 굳이 중복해 뽑지 않는다 — 기획 md를 발표 참고 문서로 쓰거나, 필요하면 개요를 뽑아 합친다.

## 요구 환경 (이식성)

- **macOS + Google Chrome**을 전제한다. `render.mjs`는 `CHROME` 환경변수 우선, 없으면 macOS 기본 경로(`/Applications/Google Chrome.app/...`)와 Linux 후보(`/usr/bin/google-chrome`, `chromium`)를 탐색. 다른 위치의 브라우저는 `CHROME=/path/to/chrome node "$SD/render.mjs" …`.
- 덱은 **폰트를 CDN(jsdelivr)에서** 불러온다 — 렌더 확인은 **네트워크가 있는 상태**에서. 오프라인이면 시스템 폰트로 폴백돼 자간이 달라 보임. 코드 장이 있으면 고정폭 폰트까지 받아야 해서 첫 렌더가 눈에 띄게 느리다.
- `node`(≥18)와 헤드리스 Chrome만 있으면 되고 별도 설치는 없음. `outline.mjs`도 의존성 없음.

## Gotchas

- **`#N` 해시 = 진입 슬라이드.** 내비 스크립트가 로드 시 `location.hash`를 읽어 그 장을 띄운다 — `render.mjs`가 이걸로 장별 스크린샷을 찍는다. 1-based(#3 = 3번째 장).
- **폰트 로드에 시간이 필요.** `--virtual-time-budget`으로 CDN 로드 + `fit()` 스케일을 기다린다 — 코드 장이 있으면 12초, 없으면 4초로 `render.mjs`가 자동 판단한다(`--wait MS`로 직접 지정).
- **코드 블록 들여쓰기는 HTML 소스 그대로다.** `pre` 안은 `white-space: pre` — 코드를 열 0에서 시작하지 않으면 슬라이드에도 그 공백이 그대로 들어간다. Prettier 는 `pre` 내부를 건드리지 않으니 서식 재정렬 걱정은 없다.
- **스테이지는 0.985로 스케일.** 1280×720 창이면 슬라이드가 여백 없이 거의 꽉 찬다 — 사용자가 보는 화면과 일치.
- **스케치 SVG는 절대 좌표.** `.sk`는 `left/top/width/height`를 인라인 지정 — 텍스트를 옮기면 스케치도 따라 옮겨야 한다. 렌더로 위치 확인 필수.
- **`.render/`는 임시물** — 덱을 두는 저장소의 `.gitignore`에 `\.render/`를 넣어 커밋되지 않게 할 것.
- **F 키 전체화면은 `e.key`가 아니라 `e.code`("KeyF")로 판별한다.** 한글 입력 모드(2벌식)에선 F 키 물리 위치가 `ㄹ`에 매핑돼 `e.key`로는 "f"가 찍히지 않는다 — `e.code`는 키보드 레이아웃/입력기와 무관하게 물리 키 위치를 그대로 주므로 IME 상태에 안 흔들린다.

## 파일

- `render.mjs` — 헤드리스 Chrome 렌더 드라이버 (이 스킬의 핵심 도구). 덱 경로를 인자로 받고 출력은 덱 옆 `.render/`에 쓴다 — 프로젝트 독립.
- `outline.mjs` — 덱 HTML → 발표자용 개요 마크다운 추출기. 출력은 덱 옆 `<덱이름>-outline.md`. 의존성 없음.
- `reference/deck-template.html` — 스타일만 추린 시작 템플릿(원형 슬라이드 11종: 표지·한 줄·불릿 3종·여정·사분면·표·코드 2종·버스트 + 마무리 + 전 CSS + 상단 디자인 브리프 주석).
